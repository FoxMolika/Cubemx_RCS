RCS CubeMX 合并安装版 0.3.4

一个 EXE：自动注册底盘软件包 0.3.4 ＋ 安装位点地图编辑器 0.2.0 ＋ Keil 头文件工具。

只需要把 RCS_CubeMX_Suite_Setup_0.3.4_win-x64.exe 复制到另一台电脑运行。安装载荷、底盘 .pack、位点编辑器、RCS_KeilHeaders.exe、任务示例和说明全部内嵌，无需额外 ZIP、Python 或手动导入 .pack。目标电脑需要已经安装完整 STM32CubeMX（已验证 6.18.1）。

在另一台电脑上安装

  1. 先安装/确认完整 STM32CubeMX。此安装程序没有捆绑 ST 官方 CubeMX；已验证 6.18.1，其他版本尚未承诺兼容。
  2. 保存并关闭 CubeMX；使用实际运行 CubeMX 的同一 Windows 用户启动本安装器，无需管理员权限。
  3. 安装器自动搜索当前用户、系统安装位置和注册表。若未找到，点击“选择程序…”选择本机 STM32CubeMX.exe，不需要选 .pack。
  4. 选择套件保存目录（默认 LocalAppData\RCS_CubeMX_Suite_0.3.4，也可选空目录）。点击 安装 / 修复。
  5. 安装器释放内嵌文件、调用本机 CubeMX 自动导入 RCS.Chassis 0.3.4，再检查注册 XML 和包内全部文件哈希。两项都通过才显示成功。
  6. 安装完成后可点击“启动地图编辑器”绘图；地图请保存到自己的资料目录。

安装记录：install-success.xml；包所有权收据：cube-pack-receipt.xml；导入日志：import-pack.log；失败详情：suite-error.log。以上文件都在所选套件目录。

在 CubeMX 里生成底盘

  1. 打开 F407 HAL 工程，进入 Software Packs → Select Components，找到 RCS.Chassis 0.3.4，勾选 Robotics / Chassis。
  2. 进入左侧 Middleware and Software Packs → Chassis，再次启用 Robotics Chassis 模式。
  3. 填写轮型、轮径、轮距、CAN、电机 ID 与控制参数，然后点击 Generate Code。底盘仍生成独立 3 个 .c 和 4 个 .h，不向 main.c 插入底盘逻辑。
  4. 为工程完成一次“关联工程…”后，后续Generate Code会自动将4个头文件登记到Keil工程树。

0.3.4 使用独立版本目录，保留已有 0.2.0/0.3.0 包，不覆盖同版本内容不同的包。旧工程可继续选旧版本，新工程请选择 0.3.4。已有工程要在组件选择器中明确切换版本，安装不会擅自修改 .ioc。

地图与路径

地图编辑器 0.2.0 可导入 CubeMX 生成的 rcs_config.h 保持几何与减速比一致，并读取命令超时。绘图、拖动/排序位点、填朝向/速度/停留、设置编码器有效计数后，导出 rcs_route.c/h 、rcs_nav.c/h 和 rcs_actions.c/h（路径3C3H）。路径模块及任务示例需要加入自己的工程，生成器不修改 main.c。画布是配套 Windows 窗口，未嵌入 CubeMX 内部。

完整地图编辑与编码器接入说明 · 底盘接口说明

要原地转头，连续两个位点设相同 X/Y、不同朝向。0°向右，90°向上，180°向左，-90°向下。每点到达位置与朝向后停车，再计算停留时间。

航点动作预留

地图中选择航点，点击“航点动作…”或双击动作列，可填写夹爪/舵机/升降的启动一次、完成条件、完成清理、取消清理及超时。也可在独立rcs_actions.c的USER CODE区域填写；重新导出按航点稳定ID保留手写内容，冲突保留原文件。使用rcs_route_init绑定动作，不修改main.c。模板只是预留注释，实际驱动由用户接入。完整航点动作使用说明。

修复和失败提示

  • 找不到 CubeMX：安装完整 CubeMX 或选择其 EXE；不会误报安装成功。
  • CubeMX 正在运行：保存并关闭后重新点击安装/修复。安装器不关闭用户进程。
  • CubeMX 更新组件尚未初始化（日志中的 Updater is busy）：安装器导入时跳过 CubeMX 的网络更新检查，避免该竞争；仍保留最多 4 次重试。
  • 已存在相同内容：重复安装核验通过，不重复注册；文件齐全但注册丢失时会保留备份并重新原生导入。
  • 已有同版本不同文件：保留原文件并明确失败；不要用一份不同内容的 .pack 冒充同一版本。本版安装器与 dist 使用同一个包。
  • 原生导入失败/超时：安装未完成，保存目录中的 import-pack.log 和 suite-error.log 提供细节。修复按钮会重试，失败时不建议把“手动导入 .pack”当作正常安装步骤。

卸载

重新运行此单文件安装器，选择原套件保存目录并卸载。只通过 CubeMX 移除本安装器首次引入且未被修改的 0.3.4 包；预先存在的包和其他版本保留。地图、工程和用户新增文件保留。若从安装目录里的 RCS_Suite_Setup.exe 运行卸载，正在运行的安装器自身会留在原处，可在退出后自行删除。

0.3.4 升级与失败恢复

本版合并 Fix/Claude 的固件修复，使用新版本号 0.3.4。已有 0.3.1 包继续保留，旧工程不会自动切换；新工程或升级工程请在组件选择器中选择 0.3.4。安装/重导入若失败，半成品会被隔离并恢复原包，首次安装失败后也可重试。若进程被意外关闭，下次安装会先恢复未完成操作。原包备份和失败内容位于仓库的 .rcs-chassis-transactions 目录，未确认恢复成功时不会删除。正常使用只需点击安装/修复。

验证边界

安装器未代码签名；.NET Framework 4.x 是 Windows 运行依赖。自动注册测试使用本机实际 CubeMX 和全新隔离配置/空仓库，未声称已测试另一台物理电脑或全新 Windows 虚拟机。底盘适配 F407 HAL、M3508/C620；主机侧有 1555 项检查、HAL 桥接、编译期配置检查和 C++ 链接检查。没有烧录和实车验证。底盘软件包沿用已记录的 Invalid RefComponent list 诊断，需以实际生成结果核验。详细记录见 suite/build/acceptance.json 与项目 docs/验证记录.md。

0.3.4：工程关联与编译修复

  1. 安装/修复套件后，在CubeMX启用RCS.Chassis并保存.ioc。
  2. 保存并关闭工程，点击安装器“关联工程…”或运行安装目录中的RCS_ProjectSetup.exe，选择该.ioc。每个工程只需关联一次。
  3. 关联会合并.extSettings以启用CAN HAL驱动，并登记工程内的生成后工具。旧RCS组件可切换至0.3.4，原文件有备份。
  4. 重新打开.ioc，Generate Code后4个头文件会自动加入Keil分组。若Keil已打开，选择重新加载工程。

生成后结果：RCS_Tools_034/headers-result.txt。RCS_KeilHeaders.exe只作手动诊断备用。关联不会替你指定CAN引脚或初始化硬件；CAN1/CAN2、波特率、滤波、接收中断仍需按实车配置。工程已有其他生成后操作时，工具会拒绝覆盖，需先合并操作。
