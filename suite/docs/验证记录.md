# 合并安装版 0.3.4 验收与证据

本版合并 Fix 0.3.1（包含 Claude 固件修复）到维护目录。安装器和原生包升为0.3.4，地图编辑器升为0.2.0。旧候选目录不修改；先前源码保存在build/pre_merge_032_*。

发布条件由脚本实际检查：

- `tools/verify.py`：1555项控制/运动学检查、HAL桥接、编译期约束、C++链接、包生成一致性，报告build/host_validation.txt。
- `map_editor/tools/verify.py`：编辑器72项自测、348项动作生命周期与实际生成回调检查（主机），三种轮型的严格C99编译与理想编码器闭环仿真，报告map_editor/build/validation.json。
- `suite/tools/test_transactions.py`：实际安装EXE的故障注入与重试，报告build/transactions.json。区分受控CLI夹具与真实CubeMX。
- `suite/tools/verify.py`：只复制单EXE、自动定位、全新隔离配置/空仓库、原生导入与全部哈希核验、重复安装、注册修复、保护修改和用户文件。
- `suite/tools/finish_tests.py`：实际原生生成、配置头/HAL语法检查、Keil补4个头文件及幂等、自定义仓库、原生卸载，补全build/acceptance.json。
- `suite/tools/release.py`：上述两份安装报告必须指向同一个实际EXE哈希，最终交付root dist中的单文件安装器、说明与源码ZIP。安装器内嵌PACK必须与dist/PACK字节一致。

## 事务恢复

在改动包目录前，先原子保存pack-transaction.xml，记录目标、已验证原包、保留目录和当前阶段。备份优先放在同一仓库的.rcs-chassis-transactions/<GUID>内；跨卷备用复制逐文件和完整目录清单校验。

导入失败时，不再以“目标目录不存在”为恢复前提：先隔离半成品，复制并核验原包后才结束回滚。原始异常和恢复失败原因一起保留；恢复失败时保留日志、原包与事务记录，后续安装先恢复再做同版本哈希检查。首次安装失败会隔离半成品以便重试。提交成功后仅清理经过核验的原始备份，失败内容保留，不改写全局CubeMX注册XML。

## 许可与启动

自写MIT包随程序完整保留许可。只对本包使用进程级MX_LIC_ACCEPT=true及accept导入模式，避免ask在quiet模式弹出许可对话框；只对本安装子进程跳过更新，并有界重试Updater is busy。两个开关都未写进CubeMX持久设置，兼容范围按实际验证的6.18.1限定。

## 范围

本轮原生验证使用本机CubeMX6.18.1和新建的隔离配置/仓库，不是另一台物理电脑或全新Windows虚拟机。未实车、未烧录、已对修复后的用户tester123副本做ARM Compiler6.22完整重编译和链接，未做烧录；程序未签名。生成日志的Invalid RefComponent list诊断仍保留，以实际文件校验为准。Configs.xml的Cversion为0Gg3Gg4，与pdsc的0.3.4对应历史编码。

程序不自动改写旧.ioc或强删旧版本包。Keil补全工具需要每次CubeMX重新Generate后运行一次。底盘3C4H、路径3C3H独立生成，不向main.c注入底盘逻辑。

新增验收：tools/test_project_setup.py验证10个实际EXE场景，使用CubeMX自身INI解析器；tools/verify_project_integration.py验证用户无CAN配置副本、生成后自动4H、删除登记后再次生成恢复、main.c不变和ARM6.22重编译。
