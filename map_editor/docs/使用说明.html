foxmolika 位点地图编辑器

0.2.2 · Windows 原生配套扩展 · 麦轮 / 三全向 / 四全向 · 编码器闭环路径执行（本套件搭配 RCS.foxmolika 0.3.6）

绘制场地、障碍物和行驶位点，自动计算编码器运动参考值，导出独立的 rcs_route.c/h + rcs_nav.c/h + rcs_actions.c/h。配合现有 RCS.foxmolika CubeMX 扩展使用。此版绘图界面是独立 Windows 程序，未嵌入 CubeMX 窗口。

1. 安装后，从哪里打开地形编辑器？

地形／地图／路径编辑器是同一个程序。在合并安装器中点击 “启动地图编辑器”；或者在资源管理器地址栏输入 %LOCALAPPDATA%\foxmolika_CubeMX_Suite_0.3.6，双击 foxmolika_MapEditor.exe。安装时改过目录的，请使用自己选择的目录。当前是独立窗口，未嵌入 CubeMX。
  1. 使用单文件 foxmolika_CubeMX_Setup_0.3.6_win-x64.exe 完成“安装 / 修复”；编辑器 0.2.2 已包含在里面，无需另装或手动导入 .pack。
  2. 需要 Windows 的 .NET Framework 4.x，运行不需要 Python 或 clang-format。单独便携版也可直接运行 foxmolika_MapEditor.exe。
  3. 底盘工程每个都要主动关联一次：在 CubeMX 选择并启用 RCS.foxmolika 0.3.6，保存 .ioc 并关闭工程 → 合并安装器最右侧 “关联工程…” → “选择 .ioc 并关联 / 升级” → 重新打开 .ioc 再 Generate Code。Keil 重载后会显示底盘的 4 个 .h。结果日志在 foxmolika_Tools_036/headers-result.txt。
  4. 上述关联不负责添加地图导出的 3C3H；仍须按本页第4节加入路径文件和自己的任务。地图保存为 .rcsmap.json，与 .ioc 分开保存。

旧 RCS 工程需先在 CubeMX 取消旧组件并启用 foxmolika；如有旧 RCS 生成后操作，先清除该旧工具再用本版关联。公开 RCS_* 接口和 .rcsmap.json 格式继续兼容。

2. 画地图和路线

  1. 启动后显示一条示例路线。点击“新建”可以清空地图。左栏输入场地宽、高和网格间距，单位均为 mm。
  2. 点击“＋ 位点”，在画布上依次点击；P0 是起点，后面的编号就是行驶顺序。点击“选择 / 拖动”移动点。右侧表格可以精确输入 X、Y、朝向、目标速度及停留秒数。
  3. 朝向是世界坐标中的车头角度：0° 向右，90° 向上，正角度逆时针。界面 Y 轴向上；底盘输出接口则使用车体 X 向前、Y 向左。
  4. 点击“▧ 障碍”，在画布上拖出矩形；在“矩形障碍”表格中修改尺寸。选择模式可拖动整个障碍物。
  5. 滚轮缩放，中键平移，“适配画布”恢复全图。“吸附网格”控制对齐。选中位点后可上移、下移；Delete 删除画布选中元素。Ctrl+Z / Ctrl+Y 撤销重做，Ctrl+S 保存，Ctrl+Shift+S 另存。
  6. 保存为 .rcsmap.json，可以继续编辑。路线预览是理想匀速动画，未模拟电机、加减速、定位误差或打滑。

此版由你指定路线，不自动绕障。检查按“车体包络半径＋到点位置容差”膨胀障碍矩形，角部为保守的方形膨胀。相切也判冲突。车体半径必须覆盖外壳、轮子和外伸机构，不能只填车体中心到轮中心的距离。它是设计时几何检查，不能保证实车跟踪中不会偏出走廊。

3. 底盘与编码器参数

建议点击“导入 CubeMX 的 rcs_config.h”，选择现有 CubeMX 工程生成的头文件。会导入轮型、轮径、轮距、全向轮半径及 W0 位置角、减速比、电机端最大 RPM；0.2.2 还会读取底盘命令超时。再次更改 CubeMX 底盘配置后，请重新导入并重新生成路径文件，两个模块的几何参数必须一致。

参数含义
轮型0：四麦轮 X 型，W0/W1/W2/W3 = 左前/右前/左后/右后。1：三全向，2：四全向。全向轮正滚动方向为轮位置角的逆时针切向。
有效计数 / 电机转填解码之后每电机转总计数。1000 线 AB 编码器四倍频应填 4000；已给“counts/rev”的数值不再乘4。所有轮假设使用同样轮径、减速比和编码器分辨率。
总减速比电机转数 / 轮转数。实际测量或使用准确规格，不应凭示例默认19认定真实减速比。
方向 ±1原始编码器正计数映射到该轮逻辑正方向；与驱动电机方向是两个配置，不自动复制。传给导航的是未翻转的原始增量，导航只翻转一次。
采样间隔、单段超时运行时必须传真实 dt 和各轮新鲜反馈掩码。缺少任一在用轮、超时、突跳会锁定故障。示例最大间隔100ms不代表可以低频读取C620角度。“允许采样最大间隔 ms”，导出前检查它小于底盘命令超时。

例如：轮径100mm，有效计数4000/电机转，减速比2。轮行进1m所需约 1/(π×0.1)×4000×2 ≈ 25465 计数。减速比和四倍频各计算一次。

C620 的角度反馈不是累计里程。0～8191角度先在接收层按采样顺序解绕，再累计到本控制周期；高速下两次接收之间超过半转，单靠角度无法消除回绕歧义。应足够高频采样，检测丢帧/歧义；无法确认时给失效掩码并停车。编码器位于轮轴时，请先按减速比换算到电机端等效计数，或对整套底盘统一使用轮轴转速和减速比1。

4. 导出与加入 CubeMX 工程

  1. 底部显示“路线检查通过”后，点击“导出 C / H”，选择新文件夹或本版生成的六文件目录。无效路线拒绝导出；更新保留USER CODE，旧目录另作备份，冲突不覆盖。
  2. 生成6个文件：rcs_route.c/h（参数和位点表）、rcs_nav.c/h（里程计和路径执行）、rcs_actions.c/h（航点动作）。
  3. 把这6个文件放到工程自己的 Application/Route 文件夹，并在 Keil/CubeIDE 的工程管理中加入三个 .c 文件及头文件搜索路径。现有 CubeMX 扩展提供 rcs_chassis.c/h；未安装该扩展时，可使用安装目录 sdk 下同名文件。同名底盘实现只编译一份。
  4. CubeMX 重新生成不会替你添加这三个源文件，也不会自动调度路线任务。下面的接入逻辑写在你自己的任务 .c/.h 中。编辑器不会改 main.c。

5. 在自己的控制任务中调用

下列是接口流程示例，不直接开机运行。先调好原有底盘速度环、方向、CAN反馈及看门狗。导航输出为车体速度，经原有 RCS_SetVelocity → RCS_Process 发送。

#include "rcs_route.h"
#include "rcs_hal.h"
static rcs_navigator nav;

/* 在自己的任务初始化中： */
if (!rcs_route_init(&nav, 0)) { /* 初始化失败，保持停止 */ }

/* 人工把车辆放到 P0，车头与 P0 朝向一致；
   清空接收层已累计的旧编码器增量，然后执行一次： */
rcs_nav_reset(&nav, rcs_route_points[0].x_m,
              rcs_route_points[0].y_m, rcs_route_points[0].yaw_rad);

/* 每个控制周期（例如10ms）的伪代码： */
int32_t delta[4];  /* 从接收层原子取出并清零的原始增量，按W0..W3排序 */
uint8_t fresh;    /* 各在用轮都必须有新测量；W0对应bit0 */
float dt;         /* 单调时钟测得的本次真实秒数 */
/* ReadAndClearEncoderDeltas(delta, &fresh, &dt); 自行实现 */
float velocity[3];
if (!rcs_nav_update(&nav, delta, fresh, dt, velocity)) {
    RCS_Lock();   /* 发送层继续周期运行，以便实际发出零电流 */
} else if (nav.state == RCS_NAV_RUNNING) {
    if (!RCS_SetVelocity(velocity[0], velocity[1], velocity[2])) {
        rcs_nav_stop(&nav);
        RCS_Lock();
    }
} else {
    RCS_SetVelocity(0, 0, 0); /* 停止/完成也必须主动发零命令 */
}
/* 按原有 RCS_PERIOD_MS 单独调度 RCS_Process，包含锁定期间。 */

/* 收到起跑指令时：先保证 reset 后已有一次新鲜导航更新，
   且控制器可解锁，再调用 RCS_Arm 和 rcs_nav_start。
   任一失败就 RCS_Lock；不要在周期里自动反复解锁。
   停止指令：rcs_nav_stop(&nav); RCS_Lock(); */

fresh 不能因为“数值没变”就认为失效：新收到的零增量是有效静止反馈；反过来，旧数据不能重复声明新鲜。fresh只是一份接口声明，接收层仍需校验时间戳、序号和帧完整性。导航函数无法在“任务完全未执行”时停车，所以必须保留底盘命令超时看门狗。三全向只检查bit0～2，W3不用。

6. 执行行为与当前边界

  • 默认停止，显式定位、获得新反馈、人工起跑后才进入运行。不能把软件重置坐标当成物理定位。停止后重新起跑需重新定位；故障锁定，需要明确重置。
  • 采用轮式编码器里程计、常体速度精确SE(2)积分、位置/朝向比例控制，平移和旋转可同时进行，带速度与加速度限制。底盘运动学进一步按电机最大RPM同比例限幅。
  • 每个位点要求位置和角度同时到达，速度降下来后执行启用的动作，再计时停留，然后才去下一点。支持原地转向和原地停留。最后一个点输出零速度。
  • 表格中的编码器计数是理想直线平移＋最短角度匀速转动的积分参考，运行轨迹会受闭环、限幅和打滑影响；控制器不是按这些总计数直接停车。匀速时间不含加减速、收敛和停留。
  • 编码器会积累误差，麦轮横向打滑尤为明显。此版无IMU融合、外部定位、动态避障或自动规划；尚未实车验证。请先架空确认每轮方向和反馈，再低速调参。

航点动作 · 地图编辑器 0.2.2 / 套件 0.3.6

选择航点，点击工具栏“航点动作…”，或双击表格的“动作”列。勾选启用，填写名称和超时。夹爪、舵机、升降三个模板只插入注释，实际函数由你的硬件驱动提供。

每个航点有四个区域：启动一次、完成条件、完成清理、取消/故障清理。公共头文件页用于填写驱动头文件。一个航点可在启动区域调用多个机构，在完成条件中组合 `&&`，表示都完成后继续。

例如升降动作（函数名仅作接口示意，需替换为队内真实接口）：

/* 公共头文件 */
#include "lift.h"

/* 启动一次 */
Lift_MoveTo(120.0f);

/* 完成条件：填写表达式，不填写 return 或分号 */
Lift_IsAtTarget()

/* 完成清理 */
Lift_StopOrHold();

/* 取消 / 故障 */
Lift_Stop();

没有完成反馈时可使用 `elapsed_s >= 0.5f` 等时间条件。默认完成条件 `1` 会在启动后的下一个有效控制周期完成，表示预留空动作，不代表机构真正动作成功。模板不会自动连接 GPIO、PWM、CAN 或具体舵机驱动。

导出得到独立的 **rcs_route.c/h、rcs_nav.c/h、rcs_actions.c/h（3C3H）**，不修改 main.c。工程中需要编译三个 `.c`，加入对应头文件搜索目录，并保留原底盘实现。用 `rcs_route_init(&nav, context)` 初始化，会同时绑定动作；只有 `rcs_nav_init` 而未绑定启用的动作时，起跑会拒绝并报告 ACTION_CONFIG。现有 `robot_route_task.c/h` 示例已使用该入口。

执行顺序为：位置、朝向到达且速度降下 → 启动一次 → 每个有效周期检查完成 → 完成清理一次 → 航点停留 → 下一点。起点 P0 和终点同样支持动作。动作期间输出零底盘速度，仍检查编码器和采样时间；不会继续修正车体位置。漂移超过 `max(2×位置容差, 50mm)` 或 `max(2×角度容差, 0.1rad)` 会故障并取消动作。运动段超时不累计动作等待，动作使用自己的正值超时（0.001～3600秒）。超时优先于同周期的完成检查。

停止、重置、反馈失效、漂移、动作超时或回调返回 `RCS_ACTION_ERROR` 时，正在运行的动作执行一次取消清理。完成后不再调用取消清理，因此停止升降或保持位置应写在“完成清理”中。取消清理本身不保证物理机构安全，必须接入真实驱动。停止后的重新定位和起跑从 P0 重新执行，已完成动作也会重新执行。停止后再初始化导航，不能用 init 代替 stop。

所有代码在导航任务里调用，必须快速返回，不能使用 HAL_Delay、阻塞循环或在回调里重新调用导航 API。超时检查无法抢占阻塞的用户代码，底盘命令看门狗也不能替代机构自己的限位和保护。上位机路线预览只播放路径，不执行用户 C 代码，也不模拟机构时间。

类似 CubeMX 的手写区域

导出的 `rcs_actions.c` 包含如下区域，实际标识使用航点稳定 ID：

/* USER CODE BEGIN WP_..._ENTER */
/* 在这里填写启动代码 */
/* USER CODE END WP_..._ENTER */

也有 POLL、DONE、CANCEL、公共 INCLUDES 和 GLOBALS 区域。可以直接在这些区域里写 C。编辑器会按航点 ID 保留手写内容，拖动或排序不会改变关联；保存地图时保留这些 ID。不要更改标记和区域外的生成内容。

可向同一个本版生成目录重新导出。生成器先核对全部六个文件，在临时目录完成合并，再替换目录；旧目录备份为相邻 `.rcs-route-backup-<ID>`，可自行归档。只有这六个文件组成的目录允许更新；IDE工程、旧版四文件目录或混有其他文件的目录应导出到新文件夹。

如果同时在界面和 `.c` 修改了同一个区域，或者删除了仍含手写代码的航点，生成器会拒绝覆盖并保留原文件。先统一两边代码，或导出新目录后手动合并。仅在界面里编辑的代码由地图保存；仅在 C 里编辑的代码在导出目录及备份中，请一并保存。地图不自动吸收 C 文件中的修改。

本版为预留硬件接口，已经做主机编译、动作生命周期、故障与保留区域测试；没有接真实夹爪、舵机或升降机构验收。

7. 文件与卸载

地图文件请保存到自己的资料目录。安装器只写选择的安装目录，不关联文件类型，也不注册CubeMX内部绘图页面。再次运行安装器可卸载；会核验安装文件哈希，保留地图和其他用户文件。便携版直接删除程序文件即可。
