# 0.2.0 验证记录

本记录区分本机测试与真实硬件结果。没有连接智能车、没有烧录，也没有将路线当作实测定位精度保证。

0.2.0 新增航点动作、v2地图及USER CODE保留式生成，延续命令超时和轮向导入检查。本版重新执行全部编辑器、C导航、动作及任务适配测试，结果由tools/verify.py写入build/validation.json。套件0.3.4的安装验收另外验证内嵌编辑器实际二进制。

## 构建与模型

Windows .NET Framework自带csc编译Windows Forms编辑器及安装器，无运行时Python依赖。编辑器自身`--selftest`完成72项检查：JSON准确往返、v1迁移、版本/输入拒绝、几何/碰撞/数值验证、CPR和减速比、朝向与计数积分、三轮型各导出恰好6个C/H文件、陌生目录保护、main.c字节保持不变、C小数点、动作序列化、稳定ID、手写代码保留、排序关联、双边冲突和删除手写代码拒绝、区域外修改/标记损坏/超限输入拒绝。

测试中的`4000有效计数/电机转 × 减速比2`按每轮转8000计数处理。未采纳独立审查文本中将这两个量混为一个counts/motor-rev的错误示例。

## C99实际导出与闭环仿真

使用实际EXE生成三套文件，GCC以`-std=c99 -O2 -Wall -Wextra -Werror -pedantic`编译实际生成的导航/路径模块和现有底盘运动学代码。模拟器将上一周期输出速度通过实际运动学转换为电机RPM，再量化成带分数余量的整数编码器增量，送回实际导航函数。

|轮型|周期数|理想闭环用时|C断言数|
|---|---:|---:|---:|
|麦轮X|3282|32.82s|16536|
|三全向|3271|32.71s|16481|
|四全向|3271|32.71s|16481|

示例最后目标为(0.7m,3.2m,180°)，最终约(0.719m,3.2m,177.1°)，符合示例20mm/3°容差；终点命令为0。测试包含一个反向编码器，验证原始方向只应用一次。

其他测试：无反馈不能起跑、重置后必须有新反馈、缺失轮数据锁定故障、0/负/NaN/Inf/过大dt拒绝、INT32_MAX突跳拒绝、故障不能自动恢复、错误起始姿态拒绝、单段超时、停止输出零、配置无效、空/NULL输入、90°初始朝向下SE(2)积分、小转角稳定积分。小转角公式由`(1-cosf(a))/a`改为稳定半角式，避免float消减误差。

任务适配器使用HAL接口桩测试通过，未声称在真实HAL上完成全工程链接。

## 原生安装器

直接运行实际打包二进制，以`/S /D=<验收目录>`静默安装到final内的中文/空格目录；重复安装通过。已安装编辑器通过同样72项自测。核对安装EXE与分发EXE的SHA256一致。

陌生目录带有main.c时安装拒绝且原始字节保持一致；安装文件被用户修改时卸载拒绝、文件保留；恢复原文件后卸载成功、用户新增资料保持原状；无用户文件的目录完成干净卸载。安装使用邻近暂存目录写入并提交；只清理自己创建的暂存目录。

## 界面检查及中止

本轮新增动作窗口通过程序的--render-actions绘制实际WinForms控件并检查图片，修正了保存/取消按钮锚定问题，未宣称完成新的鼠标交互验收。下面保留早期版本的人工界面检查记录。

通过computer-use实际观察窗口，检查地图/位点/参数/计数表布局，拖动P1从(4200,600)到(4000,700)，表格与计数同步；Ctrl+Z恢复原值。目录选择检查发现旧式树状选择框不便输入路径，随后改为可直接输入路径的导出对话框；轮型改为中文下拉框，表头禁用排序避免显示行序与执行顺序不一致。

再次打开最终窗口准备检查新导出对话框时，用户按物理Esc停止Computer Use；此后未调用任何界面操作工具，也未关闭或终止其窗口。最终导出逻辑已经在实际EXE自测中验证，未把未完成的最终对话框交互写成成功。

## 当前限制

动作新增348项主机检查：ENTER只一次、BUSY输出零、DONE完成与停留/推进、Stop/Reset/反馈失效/超时/漂移/ERROR清理只一次、错误绑定拒绝、运行中禁止重绑、实际生成的USER CODE完成与取消。夹爪、舵机、升降只预留接口；实际硬件函数必须由用户提供。回调非阻塞，软件超时不能抢占HAL_Delay等阻塞代码。

独立Windows配套绘图程序，未在CubeMX内部嵌入画布；需在IDE加入路径源文件及任务调度。无自动规划/避障执行、无IMU/外部定位、无真实电机动态、无实时障碍输入。障碍物仅设计时保守几何预检。未实车验证，安装程序未签名。
