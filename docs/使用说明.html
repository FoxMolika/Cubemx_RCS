foxmolika 底盘与地图编辑器 · 0.3.6

单文件套件：RCS.foxmolika 0.3.6 ＋ 地图编辑器 0.2.2。更新：2026-11-10。

第一次使用，请先完成这两件事：
  1. 每个工程主动关联一次：安装器的 “关联工程…” → “选择 .ioc 并关联 / 升级”。完成后重新打开工程再 Generate Code，Keil 才会自动列出底盘的 4 个 .h。
  2. 打开地形／路径编辑器：安装器的 “启动地图编辑器”，或运行安装目录的 foxmolika_MapEditor.exe。它是独立窗口，没有 CubeMX 内部的绘图菜单。
安装成功只表示工具和 .pack 已就绪，不代表你的 .ioc 已关联。新建 test2 等新工程也要单独关联。
① 安装② 关联工程③ 生成与查看 .h④ 打开地图编辑器航点动作常见问题

从旧 RCS 版本切换到 foxmolika

本版在 CubeMX 中使用新包 RCS.foxmolika 0.3.6 和新组件 Robotics / foxmolika，左侧页面与启用模式也改为 foxmolika / Robotics foxmolika。旧 RCS 包继续保留，安装本版不会自动改写旧工程。

  1. 先备份工程。打开 CubeMX，取消旧 RCS.Chassis 组件，选择并启用 RCS.foxmolika 的组件；不要同时启用两套，否则会重复编译相同的 C 接口。
  2. 如已使用旧版自动补头文件，在 Project Manager 的生成后操作中，仅清除旧 RCS_Tools_035/RCS_PostGenerate.exe 等 RCS 工具；其他自定义操作应保留并合并。
  3. 保存关闭 .ioc，再用本版 “关联工程…” 关联，重新打开 .ioc 后 Generate Code 并重载 Keil。

生成文件仍为 rcs_*.c/.h，调用接口仍为 RCS_*，地图文件仍为 .rcsmap.json。这些兼容名称保留，已有任务代码和航点 USER CODE 不必因为产品改名重写。

① 安装单文件套件

  1. 本机先安装完整 STM32CubeMX。已验证版本为 6.18.1；本套件不含 ST 官方 CubeMX。
  2. 保存并关闭 CubeMX。使用平时运行 CubeMX 的同一 Windows 用户，运行 foxmolika_CubeMX_Setup_0.3.6_win-x64.exe。
  3. 确认 CubeMX 安装位置；没有自动找到时，点“选择程序…”选本机 STM32CubeMX.exe。
  4. 确认“本套工具的保存目录”，点击 “安装 / 修复”。等待自动导入和哈希核验成功，无需手动导入 .pack。

默认目录为 %LOCALAPPDATA%\foxmolika_CubeMX_Suite_0.3.6。在资源管理器地址栏粘贴该路径即可打开；如果安装时改过目录，请打开自己选择的位置。运行不需要 Python 或 clang-format。

② 在 CubeMX 选好组件，再主动关联工程

  1. 打开 STM32F407 HAL 工程，工具链选择 MDK-ARM。
  2. 进入 Software Packs → Select Components，选择 RCS.foxmolika 0.3.6 下的 Robotics / foxmolika 组件。
  3. 在左侧 Middleware and Software Packs → foxmolika 中，启用 Robotics foxmolika 模式。填写轮型、轮径、轮距、CAN、电机 ID 等参数。
  4. 保存 .ioc 并关闭 CubeMX 中这个工程。关联会修改 .ioc；关闭后操作可避免 CubeMX 用内存中的旧配置覆盖修改。
  5. 回到套件安装器，在“安装 / 修复”“启动地图编辑器”等按钮的同一行，点击最右边的 “关联工程…”。安装器已关闭时，可重新运行它，确认保存目录仍是安装目录；也可以直接运行安装目录的 foxmolika_ProjectSetup.exe。
  6. 弹出的“foxmolika 工程关联 0.3.6”窗口中，点击 “选择 .ioc 并关联 / 升级”，选择该工程的 .ioc 文件，等待“完成”。
  7. 重新打开刚才的 .ioc，检查选中的 foxmolika 组件为 0.3.6，再执行下一步 Generate Code。
关联范围：每个工程一次；新工程需要重新关联。它会合并 .extSettings 以启用 CAN HAL，并把工程内的生成后工具登记到 CubeMX。已有 foxmolika 组件可升级到本版；旧 RCS 工程按上方切换步骤操作，原 .ioc / .extSettings 留有 .rcs-before-036 备份。工程已有其他生成后操作时会拒绝覆盖，需要先合并操作。

关联不替你配置物理 CAN 引脚、波特率、滤波器或接收中断。请按硬件接线配置 CAN1 / CAN2；选择 RCS_CAN_BUS 只选择使用哪个句柄。

③ Generate Code 后，查看独立的 .c / .h

  1. 在重新打开的 CubeMX 工程里点击 Generate Code，等待生成后操作结束。
  2. 打开 Keil 的 MDK-ARM/工程名.uvprojx。如果 Keil 已经打开，接受“重新加载工程”，或关闭后再打开。
  3. 展开底盘分组（通常为 Middlewares/foxmolika/Robotics/foxmolika）：应直接看到下面 3 个 .c 和 4 个 .h，无需先编译。
文件作用／位置
rcs_chassis.c / .h
rcs_control.c / .h
rcs_hal.c / .h		运动学、速度环与 HAL 适配。通常位于 Middlewares/Third_Party/RCS_Robotics/RCS_foxmolika/。
rcs_config.h由 CubeMX 参数生成；实际位置随工程结构可能为底盘目录、Inc/ 或 Core/Inc/。在 Keil 中右键文件查看路径即可确认。

自动补全日志：foxmolika_Tools_036/headers-result.txt。保留工程里的整个 foxmolika_Tools_036 文件夹，生成后工具使用相对路径。foxmolika_KeilHeaders.exe 是手动诊断备用，不是正常流程中每次都要运行的步骤。

生成器不向 main.c 插入底盘逻辑。请在自己的任务文件里绑定 CAN、接收反馈，周期调用 RCS_Process，并按需要调用 RCS_Arm、RCS_SetVelocity、RCS_Lock。默认 PID 为零，必须按实车调参。

④ 地形／地图／路径编辑器在哪里打开？

这三个叫法指的是同一个配套程序：foxmolika 位点地图编辑器 0.2.2。

打开方式具体操作
安装器中打开运行本套件安装器，确认保存目录，点击 “启动地图编辑器”。
直接打开资源管理器地址栏输入 %LOCALAPPDATA%\foxmolika_CubeMX_Suite_0.3.6，双击 foxmolika_MapEditor.exe。自定义安装位置请用对应目录。

当前版本在独立窗口中绘图，并未嵌入 CubeMX。不要在 CubeMX 的插件菜单中寻找绘图入口。

  1. 点击“新建”，设置场地宽、高与网格（mm）；用“＋ 位点”在画布放点，用“▧ 障碍”画矩形障碍。
  2. 在表格中设置 X、Y、朝向、速度、停留。0° 向右、90° 向上；连续两个点用相同 X/Y、不同朝向即可原地转头。
  3. 导入底盘的 rcs_config.h，核对轮径、布局、减速比；按实际编码器设置每电机转的有效计数和各轮方向。最大采样间隔须小于底盘命令超时。
  4. 将地图保存为 .rcsmap.json，它与 CubeMX 的 .ioc 是两个不同文件。
  5. 路线检查通过后点击 “导出 C / H”，得到 rcs_route.c/h、rcs_nav.c/h、rcs_actions.c/h，共 3C3H。
  6. 将路径模块加入自己的工程，编译三个 .c 并加入头文件搜索目录，在自己的任务中调用 rcs_route_init 和导航更新接口。安装目录的 examples/robot_route_task.c/h 提供接入示例；编辑器“使用说明”有完整编码器接口说明。

自动补全的范围是底盘 4 个 .h。地图导出的 3C3H 仍需主动加入工程，关联工具不会替你添加路径任务。地图里的障碍物用于路线检查，本版没有自动规划、动态避障或外部定位。

航点插入夹爪、舵机、升降动作

选择航点 → “航点动作…”，或双击动作列。填写启动一次、完成条件、完成清理、取消清理与超时；也可导出后在 rcs_actions.c 的 USER CODE 区域接入自己的驱动。预留区不包含真实机构驱动，默认完成条件 1 只表示空动作完成。

执行顺序：到达位置与朝向并减速 → 启动动作 → 逐周期检查完成 → 完成清理 → 停留 → 下一点。用户代码必须快速返回；时间等待用完成条件，避免阻塞延时。使用 rcs_route_init 绑定动作。

0.2.2 使用可读的模板生成代码，保留航点稳定 ID 和 USER CODE。重新导出会保留手写内容，不重排用户区；同一区域同时在界面和 C 文件中改动会拒绝覆盖。地图和导出的 C 文件都应保存。

常见问题与恢复

现象检查顺序
安装成功，但 Keil 看不到 .h确认是当前这个 .ioc 已关联 → 保存关闭后重新打开 .ioc → Generate Code → 查看 foxmolika_Tools_036/headers-result.txt → Keil 重载。只安装 .pack 或创建新工程不会自动关联。
生成后日志不存在确认工程内生成后工具文件夹存在，CubeMX 使用的是关联后的 .ioc；查看 Project Manager 的生成后操作是否指向 foxmolika_Tools_036/foxmolika_PostGenerate.exe。不要覆盖已有的其他操作。
找不到地图编辑器确认安装器保存目录正确，点击“启动地图编辑器”；或直接运行目录中的 foxmolika_MapEditor.exe。只手动导入 .pack 不会安装编辑器。
CAN HAL 未启用／找不到 CAN 类型完成关联再重新生成，检查 HAL 配置中的 CAN 模块与驱动源文件。硬件初始化仍需自己配置。
导入失败或包被修改查看安装目录的 import-pack.log、suite-error.log。安装器核验全部文件，拒绝覆盖同版本的不同内容，保留其他版本和用户资料。修复失败的事务保留在仓库 .foxmolika-tx。

卸载：重新运行安装器，选原目录，点击“卸载此套工具”。只移除本套件引入且未被修改的包和工具；工程、地图及用户新增文件保留。

适用范围：Windows x64、STM32F407 HAL、M3508/C620；已验证 CubeMX 6.18.1。其他 IDE 的头文件自动登记、CubeMX 内嵌绘图、真实机构驱动不在本版范围。安装器未代码签名；未烧录或实车验收。完整验证和版本比较见随源码交付的 docs 目录。
