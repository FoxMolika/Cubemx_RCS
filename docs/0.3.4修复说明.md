# 0.3.4修复说明

用户日志中的unknown CAN_HandleTypeDef并非许可证问题：tester123.ioc仅启用NVIC、RCC、SYS，未启用CAN，HAL配置中CAN关闭且工程未登记CAN驱动源文件。头文件没有进入Keil工程树则是另一个问题，0.3.3只提供手动工具，未自动运行。

安装新版单文件套件后，点击“关联工程…”选择.ioc；重新打开并Generate Code。每个工程关联一次，以后只需正常生成。已修复的tester123副本在dist/tester123_fixed_0.3.4.zip，原test目录和0.3.3发行目录保持不动。

关联内容：合并.extSettings启用CAN HAL；保存生成后操作，调用工程内RCS_Tools_034/RCS_PostGenerate.exe；自动补4个头文件。首次修改保留*.rcs-before-034，UV项目首次补头保留.uvprojx.rcs-backup；其他生成后操作和被修改的工具不会被覆盖。

硬件CAN引脚、波特率、滤波器和接收中断需要按接线配置。RCS_CAN_BUS只是底盘选择使用CAN1还是CAN2，不会替你配置芯片外设。关联后能编译并不表示已完成实车驱动接入。生成器不会向main.c加入底盘调用。

修复副本用本机Keil ARM Compiler6.22完成真实重编译及链接：0错误0警告，并生成axf。沙箱内armasm出现DLL重定位错误，沙箱外同一源码编译通过；无烧录。验收同时检查每次生成后的头文件登记、CAN HAL驱动及main.c字节不变。

后续更新CubeMX或更改工具链需要重新验证。本版仅验收CubeMX6.18.1、F407 HAL和Keil MDK。地图仍是0.2.0独立配套窗口，嵌入实验在另一目录。
