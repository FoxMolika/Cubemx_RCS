# 0.3.5 与 DeepSeek/Fix 版本的实际差异

比较日期：2026-11-10。对照目录为 `RCS_Chassis_CubeMX_Fix`，其底盘版本0.3.1、地图编辑器0.1.1。该目录安装器SHA-256：`9a550a169b49470fd7707bd151b2055592a54de277e67eee6043cc69055e55e5`，与用户提供的报告一致。该目录与原0.3.4目录保留，0.3.5单独开发。

## 对 DeepSeek 判断的结论

“原先代码太紧凑、注释和分区不够像队内HAL模板”的判断成立。其六个固件文件的可读性改进值得采用；0.3.5以这些排版和中文Doxygen为基础，保留公开RCS接口和原有修复。

但“相似度不足”需要区分排版与实现：队内HAL模板含C++电机/执行器类及FreeRTOS CAN订阅，而STD模板有TAB、头文件保护宏和UCOS任务。它们并不是同一种风格。本生成器仍输出纯C F407 HAL模块，没有移植队内RTOS/C++架构；行宽、注释比例和1555项测试均不能证明功能相似度百分比。

DeepSeek检查器也不等于它声称的全部规则：四空格缩进没有实际校验，分号检查将含`for (`的整行豁免，函数注释主要按少数返回类型及前16行粗查。已用其原六文件副本复现：把一条8空格`return`改成2空格，旧检查仍通过；新检查拒绝。此结果仅说明具体漏检，不能据此否定其全部修改。

## 生成与功能差异

| 项目 | DeepSeek/Fix 0.3.1 | 本版0.3.5 |
|---|---|---|
| 风格覆盖 | 6个静态固件文件 | 13个实际输出C/H：底盘7个、路径6个 |
| 配置头 | 不在六文件风格检查范围 | 离线与CubeMX共用前缀/约束段，原生生成也检查 |
| 地图生成 | 旧地图0.1.1 | 地图0.2.1：route/actions改用内嵌模板，nav同步排版 |
| 检查方式 | 行级启发式、未校验4空格 | 注释/字符串词法屏蔽、真实for括号识别、块缩进、相邻函数文档；仍是有限的项目风格检查器，不是完整C解析器 |
| 用户代码 | 该候选版本没有目前的航点动作生成链 | 沿用0.2.0动作/稳定ID/USER CODE机制，升级保留手写代码与冲突保护；用户区不重排 |
| CAN未启用 | 缺少0.3.4新增的明确保护 | 保留明确#error与工程级CAN HAL依赖关联 |
| Keil头文件 | 手动工程修正工具 | 保留0.3.4的每工程关联、生成后自动登记4H |
| 安装恢复 | 旧修复安装逻辑 | 保留已持久化的失败事务恢复与原文件保护 |
| 网页教程 | 不包含目前的关联流程/新动作入口 | 首屏说明主动关联、按钮位置、重开.ioc、Keil重载、编辑器两种启动方式 |
| 用户运行依赖 | .NET/CubeMX | 同类依赖；无需Python或clang-format，模板直接内嵌EXE |

工程关联、CAN依赖、安装事务、航点动作是相对DeepSeek候选版本的差异，主要继承自0.3.4/地图0.2.0；本次新增重点是模板生成方式、完整风格覆盖、兼容性验证和教程重写。

13个输出清单：`rcs_chassis.c/h`、`rcs_control.c/h`、`rcs_hal.c/h`、`rcs_config.h`、`rcs_nav.c/h`、`rcs_route.c/h`、`rcs_actions.c/h`。开发检查器覆盖模板输出；运行时地图程序另有内置基础策略检查。USER CODE及机器校验标记有明确豁免，不声称任意手写C都遵守生成格式。

## 可复查的描述统计

六个核心固件文件使用同一统计脚本，按非空行统计。注释占比只计“只有注释”的行，不等于DeepSeek报告采用的全部注释口径。

| 六文件样本 | 非空行数 | 平均每行字符数 | 纯注释行占比 |
|---|---:|---:|---:|
| 原0.3.4 | 327 | 45.90 | 6.73% |
| DeepSeek候选 | 794 | 31.31 | 29.97% |
| 新0.3.5 | 883 | 29.62 | 39.98% |

队内HAL归档中仅取`RCS/RCS_HAL/`的17个C/H样本：平均31.66字符、纯注释行39.55%，实际也有TAB。STD归档仅取USER、排除.cmsis的54个可解码C/H样本：平均66.24字符、纯注释行22.59%；`USER/system_stm32f4xx.c`无法按严格UTF-8或GB18030解码，明确排除。STD样本仍含支持代码，不能视为全由队员手写。范围不同，不能把这些数值换算成“相似度”。

脚本`tools/style_audit.py`保存归档SHA、选样列表、解码方式和排除原因。随源码ZIP提供`suite/validation/style-audit.json`，可核查统计口径。

## 验证证据与使用边界

本版发布脚本要求以下检查全通过且绑定最终EXE哈希；原始本地报告位于build，发布副本位于源码ZIP的`suite/validation/`：

- 固件1555项、HAL桥接、编译期非法配置/CAN负向检查、C++链接。
- 地图实际EXE72项、三轮型理想编码器闭环模拟、349项动作检查。
- 17个风格/导出场景：旧检查器反例；实际地图编辑器0.2.0输出升级到0.2.1，保留手写代码和字面模板标记，重复导出字节一致，双边修改拒绝覆盖。源码包另带实际旧输出及哈希供没有旧EXE时重现。
- 实际安装器事务、隔离配置与空仓库安装/修复/卸载、安装后编辑器自测；CubeMX6.18.1原生生成与实际安装后的关联工具。
- 新项目副本连续生成两次、删除4H登记后再生成自动补齐、main.c保持原字节；Keil ARM Compiler6.22完整Rebuild并链接，0错误0警告。
- 三个HTML教程的当前入口、路径、版本与链接检查；安装器直接内嵌更新后的套件和地图教程。

本轮委派给DeepSeek的两项任务是基于给定上下文的并行审查建议，委派工具没有本地文件或测试执行能力。Codex负责对照代码、复现漏检、实施修改、运行实际工具链并核对发布工件；这不代表对原DeepSeek候选版本作者工作方式的判断。

仍需每个工程主动关联一次；地图是独立窗口，路径3C3H需要自己加入工程；真实机构驱动、CAN板级配置、任务调度需要接入。没有实车、烧录、其他物理电脑或全新Windows虚拟机验收。
