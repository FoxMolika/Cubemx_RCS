## 产品边界

| 影响 | 0.8.4 的行为 | 0.8.5 的修复与验证 |
| --- | --- | --- |
| 高 · 并发写入 | 第二个编辑器看到待办日志时，可能回滚第一个编辑器正在提交的硬件文件。 | 同一应用目录的硬件导出与恢复共用独占文件锁。回归在提交过程中启动第二个进程，验证恢复请求被拒绝，首个进程可以继续提交。 |
| 高 · 恢复中断 | 导出已提交，清理部分备份后遇到文件占用，下一次恢复仍要求读齐全部备份，工程的预构建和后续导出会被遗留日志阻塞。 | 恢复区分待回滚、已提交和已还原。回归通过真实文件占用使清理中断，释放占用后重试，核对交付文件摘要以及日志和临时目录的清理结果。 |
| 中 · 清单容量 | 读端把设备和文件混算进 2048 项上限，已有目录检查又把清单计入 32 MiB，导致写端接受的交付在重读时被拒绝。 | 文件、设备上限分别为 2048 和 64，清单单独计量。测试覆盖两种数量恰好到顶和各多一项，以及驱动总量恰好 32 MiB 和多一个字节。 |
| 中 · 模板往返 | 内存校验以字符数计量，文件读取按字节限制。含多字节文本的模板可能保存成功，却无法再次打开个人模板库。 | 保存、导入和导出统一校验 UTF-8 字节数，个人模板用临时文件原子提交。含中文的模板在 3 MiB 整时保存后可重读，增加一个字节会被拒绝，原模板仍可打开。 |
| 中 · 路径归属 | 硬件驱动名的 ASCII 限制也施加在用户选定的路线目录和 Keil 工程名上。恢复对归档目录则仅检查名称前缀。 | 按实际关联的工程、已知路线文件和带有效标识的归档目录核对目标。驱动仍使用相对路径校验，中文及带空格的工程名和路线目录均已进入回归。 |

事务实现和登记逻辑见 [HardwareExport.cs](../map_editor/src/HardwareExport.cs) 与 [HardwareBinding.cs](../keil_headers/HardwareBinding.cs)。模板读写见 [HardwareCatalog.cs](../map_editor/src/HardwareCatalog.cs)。回归见 [工程与恢复测试](../tools/test_hardware_project.py) 和 [模板边界测试](../map_editor/src/HardwareTests.cs)。
