# 代码审查与重构方案

基线：GitHub `FoxMolika/Cubemx_RCS` 的 `aaeeca5`（0.8.0，含最新 README/更新日志）。本轮为结构重构，不发布新的固件版本。

## 审查结论

| 问题 | 依据与影响 | 处理 |
| --- | --- | --- |
| 坡道生成依赖整段 C 源码的字符串替换 | `TerrainMotionGenerator.cs` 把配置、采样、数据表和导航补丁放在一起；最后只检查三个字符串，不能逐一发现启动、故障保持等插入点遗漏 | 为导航源码设置可编译的注释插槽，按名称拼装；缺失、重复和未知插槽均拒绝导出。C 片段作为可读模板维护 |
| 参数、几何积分和源码拼接混在一个模块 | 原文件66行约13KB，最长行820字符；单位及过渡计算不易追踪 | 分为执行参数/校验、坡道采样、模板组合；中文注释说明单位、平滑模型和单次投影不变性 |
| 形状编辑的事务和鼠标交互过于紧凑 | 原文件86行约14KB，最长行1286字符；无效拖动回退与整次撤销难以审查 | 按画布操作和窗口入口分层，提取命中/候选变形等步骤，保留快照与撤销行为 |
| 构建脚本重复配置 | 编辑器、套件分别维护编译器调用与示例文件清单，容易漏打包 | 共用少量构建函数和文件清单，保留独立安装器入口与资源名称 |
| 验收入口耦合发布归档环境 | 完整验收依赖 CubeMX/Keil；历史核验读取旧版目录和本地快照；平地比较依赖相邻0.7目录 | 拆分主机、原生、发布三级；用已验证基准摘要做0.7平地回归；发布级继续严格要求历史证据 |

## 兼容性约束

- 保持 `RCS_*` API、地图 v3/v4/v5/v6、USER CODE 标识及合并规则。
- 平地仍为3C3H，坡道仍为4C4H；保持工程关联、自动登记头文件和重生成恢复。
- 保留底盘故障/超时保护、显式制动接入及无独立定位时不纠错的规则。
- 不改动力学、PID、坡道积分、车轮方向或坐标定义；不以模拟测试代替实车标定。
- C 模板具名插槽只作用于原模板，不递归解析用户插入内容。

## 验收与交付

1. 从基线提交构建隔离编辑器，用同一地图比较平地、坡道、制动绑定、平台转向与用户代码的实际输出。
2. 对模板丢失/重复插槽作负向测试，并重跑已有C闭环、几何、UI、迁移和工程保护回归。
3. 使用本机CubeMX和Keil验证安装、实际6/8文件生成及再生成、真实ARM编译和卸载。
4. 记录测试范围及未验证项，检查Git差异后提交推送；构建缓存、安装环境和私有编译日志不进入仓库。

## 实施结构

| 位置 | 职责 |

删除无引用的一次性 `prepare_continuous_release.py` 和 `prepare_correction_release.py`；旧实现仍在Git历史中。其他既有地图、安装器和底盘模块保留现有职责；本轮没有对全部历史代码做机械格式化。

## 确认并修复的问题

原坡道生成器试图把 `observation_seen=0; state=IDLE;` 替换为带地形复位的代码，但实际导航源码在两句之间还有 `feedback_seen=0;`，因此替换次数为零且没有错误。真实旧版生成代码中，坡道故障后调用 `rcs_nav_reset` 仍保留 `terrain.fault` 和活动航段，下一次启动继续失败。

新模板的 `NAV_RESET` 明确清除活动地形与故障；仍清除反馈标记，要求新鲜采样和显式 `rcs_nav_start`。C回归先运行基线证明缺陷，再运行新生成文件证明恢复。与基线的输出差异只允许这两条复位语句和相应生成签名。

## 开发检查

Windows环境需Python、.NET Framework C#编译器，以及PATH中的Git/GCC/G++/nm；完整Git克隆保留基线提交 `aaeeca5`。`python tools/check.py --level host` 不要求CubeMX或Keil。传统 `accept_080.py` 仍为严格release入口，支持原有 `--from`。

`--level native` 在host之上运行安装、CubeMX生成/再生成和Keil编译。现有探针沿用本机约定：CubeMX在 `%LOCALAPPDATA%/Programs/STM32CubeMX`，Keil在 `%LOCALAPPDATA%/Keil_v5`，F4固件为用户仓库中的 `STM32Cube_FW_F4_V1.28.3`；部分构建脚本支持 `STM32CubeMX_PATH`，探针尚未全部参数化，预检会明确指出缺项。

`--level release` 还要求维护者保存的旧版目录及事前SHA256快照，缺少即失败，不会自动生成“历史未改动”的证明。`--from`只表示续跑，报告不能当作本次从头执行；每项独立报告仍校验对应二进制哈希。

为避免发布数据混淆，本轮保留0.8程序集版本并只推送源码。正式新版本应单独变更版本号并执行release级核验。

- 15种地图的实际导出比较，共106个C/H文件：平地逐字节一致；坡道仅允许复位的两条语句及生成签名变化。实际基线程序已复现旧缺陷，新代码要求复位后新鲜反馈和人工启动。
- 82项模板契约检查通过：缺块、删完整块、重复、错误结束名、嵌套、块外代码及用户插入文本不递归替换。
- 底盘1555项、阶段11551项、独立纠错607项、崩溃54项，以及74项形状几何、44项交互和41项可选模块工程事务通过。
- 三种轮型、倒车、地图旋转90°和平台转向路线的真实8文件C仿真通过；973项坡道运行时和3140项任务/制动端口模拟断言通过。
- 实际CubeMX6.18.1分别生成、删除分组后再生成平地6文件和坡道8文件，头文件、包含路径、用户代码与main保持正确；ARM Compiler6.22均0错误0警告。
- Medium非管理员安装、自动导入、重复安装、修复和卸载通过；新构建资源清单与受测安装器逐项哈希一致。构建示例已验证不会改写仓内参考地图。
