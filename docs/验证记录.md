# 0.3.4 验证记录

日期：2026-11-09。测试文件、日志和缓存均在本项目目录内。本记录说明发布验收项目和证据路径；本次构建的实际执行结果以对应版本的机器报告为准，不沿用候选版本的安装器哈希。

## 组件主机侧

- GCC C99 `-O2 -Wall -Wextra -Werror -pedantic` 编译 `rcs_chassis.c`、`rcs_control.c` 和测试程序，运行 1555 项检查并全部通过。覆盖前进/横移/旋转/组合速度、轮径与减速比换算、三/四全向轮、同比例饱和、零/非法输入、正逆解一致性、PID 限幅与条件积分、超时、锁定/重解锁、时间回绕。
- 微分项作用在测量值：新增用例验证速度阶跃不产生输出、测量转速变化被 Kd 阻尼、解锁/故障恢复后无历史残留。
- HAL stub 编译并运行：CAN 通道绑定、IRQ 快照、错误帧拒绝、未解锁阻止运动、锁定立即零帧、排队旧命令取消、邮箱忙等待、`CAN_ESR.BOFF` 总线关闭及自动恢复、帧校验。
- 编译期配置检查：重复电机 ID、命令/反馈超时 ≤ 周期、方向非 ±1、布局/电流越界均触发 `#error`；三全向轮忽略 W3 的重复 ID 仍可编译。
- C++ 链接：`rcs_hal.h`、`rcs_control.h`、`rcs_chassis.h` 带 `extern "C"`，g++ 包含后符号为 `U RCS_State`，无 C++ mangling。
- 参数层：非法范围、NaN、重复 ID、非法方向、超时关系、`.ioc` 只读检查、导出目录拒绝覆盖；导出恰好 3 个 `.c` + 4 个 `.h`，已有 `main.c` 字节不变。
- 打包：同一配置重复构建 SHA-256 相同；包内条目无路径越界；pdsc 引用、Modes/Configs 声明与模板参数一致。

以上结果写入 `build/host_validation.txt`，可由 `python tools/verify.py` 重跑。

## 合并安装器与原生生成验收流程

`suite/tools/verify.py` 与 `suite/tools/finish_tests.py` 要求在本机 CubeMX 6.18.1 的全新隔离配置/空仓库上执行，覆盖：

- 只复制单个 EXE 运行；删除 `STM32CubeMX_PATH` 后自动发现 CubeMX。
- 原生导入 `RCS.Chassis 0.3.4`，核对 `updaterThirdParties.xml` 注册与包内全部文件哈希；重复安装；删除注册记录后保留包目录的修复。导入用的 CubeMX 进程设置 `MX_UPDATER_SKIP_UPDATE=true`，跳过网络更新检查，避免它与 `swmgr` 抢 updater 锁；不修改 CubeMX 安装、持久偏好或注册表。
- 已安装地图编辑器 `--selftest`。
- 安装到含 `main.c` 的陌生目录、无效 CubeMX 路径、被用户修改的包：均拒绝且保留原文件。
- 第二份工具安装不夺走既有包；卸载只移除本安装器首次引入且未修改的包。
- 已安装 0.3.4 包上执行 CubeMX 原生 Generate Code：四全向、轮径 180 mm、7 个文件与模板一致、`main.c` 无底盘钩子；`rcs_config.h` 的编译期检查与生成 HAL 头文件一起通过 `-fsyntax-only`。
- `RCS_KeilHeaders.exe` 在原生 MDK 工程上加入 4 个头文件，第二次运行不修改工程。
- 自定义空仓库与显式 `STM32CubeMX.exe` 路径安装；原生卸载和干净卸载，用户资料保留。

结果（含安装目录、测试 home、包目录、原生 `main.c` SHA-256、安装器 SHA-256）写入 `suite/build/acceptance.json`。本轮若任一检查失败，脚本会中止并保留日志，不会写入通过记录。

## 已知偏差与诊断

- 原生生成仍可能出现 `Middleware: Invalid RefComponent list` 诊断；本版未消除，以实际生成文件核验为准。
- `CubeMX/RCS.Chassis.0.3.4_Configs.xml` 的 `RefComponent Cversion` 沿用历史写法 `0Gg3Gg2`（构建脚本把 `.` 替换为 `Gg`），与 pdsc 的 `0.3.4` 字符串不同。CubeMX 6.18.1 下实测可正常生成；本轮未改此编码，避免引入未经验证的格式变化。
- 动态内存、栈占用和长时间运行稳定性未测试。
