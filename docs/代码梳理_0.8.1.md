# 0.8.1 代码梳理

本文是给"要读这份代码的人"的导航，不是变更日志。变更内容见 [CHANGELOG.md](../CHANGELOG.md)。

0.8.1 相对 0.8.0 没有新增功能，主要变化如下：

1. **修复**：Keil 工程含文件级/分组级 `<Cads>` 时，重复"关联工程"会抛 `序列包含不止一个元素`
2. **加固**：在部分导出中观察到间歇性 `ERROR_ACCESS_DENIED`（根因尚未确定），改为受限重试 + 完整诊断
3. **重构**：模板拼装与形状交互从两个巨型文件里拆出来
4. **统一版本**：Python唯一版本源生成C#常量、程序集、清单、教程和软件包路径
5. **文件提交**：Keil工程、地图和配置共用原子写入，逐次比对快照并覆盖1175故障回归

## 一、这不是一个程序，是六个产物

| 产物 | 语言 | 跑在哪 | 入口 | 主要职责 |
|---|---|---|---|---|
| 地图编辑器 | C# WinForms | 你的 Windows | `map_editor/src/Program.cs` | 以模型、生成、交互为主 |
| 工程关联与生成后工具 | C# | 关联工程时 / CubeMX 生成后 | `ProjectSetup.Main` / `KeilHeaders.Main` | 共用 `ProjectBinding` 处理目标级选项、原子写入与工具迁移 |
| 合并安装器 | C# | 安装时 | `suite/src/Setup.cs` | 提取、包事务和有限重试 |
| 底盘固件库 | C | STM32 目标板 | `firmware/rcs_chassis.c` | 底盘运动学、速度控制和 HAL 接口 |
| CubeMX 生成模板 | 文本模板 | CubeMX 生成时 | `templates/*.tpl` | 组件配置与参数检查 |
| 开发校验 | Python | 开发机 | `tools/check.py` | host/native/release分层检查 |

**读法核心：不要按目录读，按一条数据流读。**

## 二、主线：从点"导出 C/H"到 Keil 里多出一个分组

```
① 触发
   Program.Main           --export（仅文件）/ --export-project、--export-linked（含工程登记）/ GUI
   Editor.cs             主窗口，按钮事件
        │
② 内存模型
   Model.cs              地图 / 航点 / 表面 / 连接 的数据结构 ← 地基
   Terrain.cs             表面几何
   TerrainRouting.cs      连接、可达性、跨面链
        │
③ 生成 C 源码
   Exporter.Prepare           校验目标目录 + 合并 USER CODE
     ├ RevisionGuard.CheckSavedMap   已保存地图与当前内存模型的一致性
     ├ TemplateGenerator.Generate    用 TerrainGeometry.HasRelief 决定 3C3H 还是 4C4H
     │    ├ TemplateBlocks.Render    校验并装配具名模板块
     │    ├ SourceTemplates.Render  装配后一次替换参数；坡道片段来自 templates/terrain_*.tpl
     │    └ TerrainMotionGenerator / TerrainSampling / TerrainDriveSettings
     └ UserRegions.Merge            按稳定航点 ID 保留手写区
        │
④ 落盘（事务）
   Exporter.Export
     写临时目录 .rcs-export-<guid>
     → MoveDirectory("备份既有目录")   把旧目录挪到 .rcs-route-backup-<guid>
     → MoveDirectory("安装新目录")     临时目录转正
     → 新目录安装失败且已有备份时，尝试 MoveDirectory("回滚原目录")
     每一步检查前提与内容快照，受限重试并保留备份；不把随机失败当作已知根因
     → RevisionGuard.Record 写导出凭据
        │
⑤ 改 Keil 工程
   ProjectExport.Export   先预检并关联工程，再导出文件、绑定凭据，最后调用 KeilHeaders.Fix
   KeilHeaders.Fix → ProjectBinding.UpdateRoute
     ├ TargetCompilerOptions(target)  ← 本版本修复点：只沿目标层级取编译选项
     ├ 补 Application/foxmolikaRoute 分组与 .c/.h 登记
     └ 往目标级 IncludePath 追加输出目录
```

一句话记忆：**模型 → 模板 → 事务落盘 → 工程登记**。预检会尽早拒绝无效输入，但整条流程不是跨文件事务：暂存文件会先落盘，路线目录提交后仍可能在凭据写入或 Keil 登记时失败。`ProjectExport.Export` 对 Keil 登记失败会明确提示已保留路线文件，不能把所有失败都理解成“没有写入”。

## 四、三个"门"：解释大量"为什么导出被拒绝"

| 文件 / 函数 | 管什么 |
|---|---|
| `GeneratedPolicy.Check` | 检查文件说明、头文件保护和生成区域排版；跳过 USER CODE 的排版检查 |
| `UserRegions.Check` / `Merge` | 校验 USER CODE 标记及生成区域签名；按稳定 ID 保留手写区，拒绝生成区外改动、被删除的自定义区及双边冲突 |
| `RevisionGuard.CheckSavedMap` / `Record` / `Check` / `Bind` | 比对已保存地图、导出凭据和生成文件，绑定构建前检查；已登记门禁的工程会拒绝编译未重新导出的修改 |

这些检查保证地图、生成文件和构建输入的一致性，不是实车定位或纠错的依据。

## 五、本版两处修复怎么读

### 5.1 Keil 编译选项层级（`keil_headers/ProjectBinding.cs`）

**问题**：`.uvprojx` 里 `<Cads>` 可出现在目标、分组和文件等不同层级。

| 层级 | 位置 | 用途 |
|---|---|---|
| 目标级 | `Target/TargetOption/TargetArmAds/Cads` | 整个 target 的 C 编译选项 ← 要改的是这个 |
| 分组级 | `Target/Groups/Group/GroupOption/GroupArmAds/Cads` | 一个分组的私有选项 |
| 文件级 | `Target/Groups/Group/Files/File/FileOption/FileArmAds/Cads` | 单个文件的私有选项 |

旧代码用 `target.Descendants("Cads")`，会把分组级、文件级的也抓进来；多个块含 `VariousControls` 时，`SingleOrDefault()` 就抛异常。

**修法**：新增 `TargetCompilerOptions(target)`，逐层 `Elements()` 取直接子节点，每层校验 0 个/多个并抛中文错误。`KeilHeaders.cs` 也改为复用它——原来那里的 `FirstOrDefault()` 可能取到某个文件的空 `IncludePath`，把目标级配置遮蔽掉。

**怎么验证**：`tests/fixtures/keil_compiler_options.uvprojx` 是真实结构夹具，`tools/test_keil_options.py` 跑 13 项。

### 5.2 导出目录事务（`map_editor/src/Exporter.cs`）

导出不是"覆盖写 8 个文件"，而是**目录级事务**：

```
写 .rcs-export-<guid>
   ├─ 旧目录存在 → 改名为 .rcs-route-backup-<guid>（备份）
   ├─ 新目录就位
   └─ 新目录安装失败且已有备份 → 尝试回滚；回滚失败则报告 backup 路径供人工恢复
```

本版加固点：

| 关注点 | 实现 |
|---|---|
| 重试范围 | `MoveDirectory` 的单次移动操作只重试 Win32 `5 / 32 / 33`（ACCESS_DENIED / SHARING_VIOLATION / LOCK_VIOLATION），最多尝试 3 次，退避 60/120 ms；不会重跑整个导出流程 |
| 不盲目重试 | 每次尝试前重查源、目标、路径链接及文件清单/内容快照；前提变化立即停止，持续权限拒绝在次数耗尽后如实报错 |
| 诊断信息 | 步骤名、源、目标、尝试次数、`HRESULT`、源/目标是否存在 |
| 清理不掩盖 | 临时目录清理失败只在**没有主异常**时才抛出；主异常原样上抛（`ExceptionDispatchInfo`） |

`tools/test_export_transaction.py` 用故障注入覆盖暂时失败、持续拒绝、目标被抢先创建和回滚失败。成功提交后旧备份仍保留；如果回滚目标已被其他程序创建，不会为恢复备份而覆盖它。

**不要混淆两种提交**：目录移动使用上面的 `MoveDirectory`；单文件写入使用 `ProjectBinding.AtomicWrite` / `CommitFile`。后者对已有目标坚持使用 `File.Replace`，新目标使用 `File.Move`，每次尝试重新比对暂存与原目标快照；除 `5 / 32 / 33` 外还允许重试 `1175`（`ERROR_UNABLE_TO_REMOVE_REPLACED`），不包含 `1176 / 1177`。对应回归在 `tools/test_atomic_file.py`。这不是发现访问拒绝后修改权限或降级为普通覆盖写。

## 六、建议阅读顺序

| 天 | 读什么 | 读的时候回答 |
|---|---|---|
| 1 | `Program.cs` → `Editor.cs` | 窗口怎么起来？按钮事件指向谁？ |
| 2 | `Model.cs` → `Terrain.cs` → `TerrainRouting.cs` | 一张地图在内存里是什么？三类对象怎么关联？ |
| 3 | `Exporter.cs` → `TemplateGenerator.cs` → `SourceTemplates.cs` → `TemplateBlocks.cs` → `UserRegions.cs` | 3C3H/4C4H 的分叉在哪判断？USER CODE 怎么保住？ |
| 4 | `ProjectExport.cs` → `ProjectBinding.cs`（`UpdateRoute` / `AtomicWrite`） | 分组、文件、IncludePath 三者各写在哪？并发修改为什么不能直接覆盖？ |
| 5 | `TerrainSampling.cs` → `TerrainDriveSettings.cs` → `TerrainMotionGenerator.cs` | 坡道高度怎么变成位移？`TransitionMm` 走到哪？ |

第 3 天最关键：它决定你以后改生成逻辑会不会误伤用户手写代码。

## 八、验证怎么跑

```powershell
# 主机级：编译编辑器并运行 HOST_STEPS，不需要 CubeMX/Keil
python tools\check.py

# 原生级：真实调用 CubeMX 与 Keil
python tools\check.py --level native

# 发布级：先跑 host + native，再核对证据并打包
python tools\check.py --level release
```

用 `python tools\check.py --level release --list` 可只列出检查顺序。`tools/check.py` 的 `steps_for` 定义各层依赖；`tools/release.py` 是最后的打包步骤，**只打包、不重建或安装**，逐项检查验收 JSON、当前二进制和相关源码哈希，以及历史发布目录/快照。原生证据包括 CubeMX 生成、Keil ARM 编译零错误零警告；证据缺失或绑定内容不符就拒绝打包。`tools/release_080.py` 只是调用当前 `release.main` 的兼容入口，不代表发布固定的旧版本。


本版当前版本由 `tools/version.py` 单一生成；C#常量、安装清单和当前HTML同步生成。新增导出事务与安装器目录操作的确定性故障测试，构建和验收规则见[版本与发布](版本与发布.md)。

原子文件提交另覆盖1175替换失败；安装暂存与包备份有独立IO故障注入。当前源码行数会随修复变化，建议按函数名定位而非依赖固定行号。
