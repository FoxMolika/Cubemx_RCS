foxmolika 0.8.3.beta：应用与状态机使用说明

这是独立的本地测试工程。原来的 0.8.2 和 DeepSeek 0.8.3 目录均保留。本版没有发布到 GitHub，也没有烧录实车。

1. 现在会生成什么

固定调用链为 main → App_Task → Machism_Task → 路线与航点动作。主循环只负责调度，具体业务在编辑器中修改。

平地图导出 19 个文件；含坡道导出 21 个文件。关联工程后，所有生成的 .c/.h 和包含路径会自动登记到 Keil。CubeMX 再次生成时，工程内的 beta 生成后工具会补回登记。

  • app.c / app.h：固定 App_Init、App_Task、App_Start、App_Stop 入口。
  • machism.c / machism.h：用户编辑的业务状态、转移和用户代码区。
  • rcs_app_task.c / rcs_app_task.h：应用周期、解锁、反馈、导航、安全停止及故障快照。
  • rcs_route、rcs_nav、rcs_actions 的 .c/.h：路线、导航和逐航点动作。
  • rcs_can_port、rcs_feedback_port 的 .c/.h：CAN 收帧与电机原始角度采集。
  • 三个配置头文件：应用启动、反馈采集，以及旧版定位宏兼容头。实际纠错从地图硬件档案和纠错模板生成；单改旧宏不会启用定位。
  • rcs_terrain.c / rcs_terrain.h：地图含坡道时生成。

CubeMX 的底盘组件仍生成底盘速度环及 rcs_config.h。地图导出负责应用与路线；只点 CubeMX Generate、尚未导出地图时，不会凭空得到航点业务。

2. 先准备硬件配置

当前自动运动链支持 STM32F407、HAL CAN，以及使用 DJI C620 转子角反馈协议的电机。反馈 ID 为 0x201～0x204，计数为 8192/电机转；轮轴计数和减速比不能混用。其他电机协议或外置编码器需要明确的适配器，不能仅换一个轮径就视为已支持。

在 CubeMX 中启用实际使用的 CAN、配置引脚和位时序，并启用对应 CAN RX0 中断。生成的 IRQHandler 必须调用 HAL_CAN_IRQHandler。CAN2 还需要正确的 CAN 时钟依赖。实际引脚、波特率、终端电阻和电机 ID 必须与接线一致。

底盘参数设置轮型、轮径、轮距或全向轮半径、W0 安装角、减速比、电机 ID、方向、速度环 PID 和电流限幅。默认 PID 全零不会被当成可试车配置；启用应用运动后 App_Init 会明确拒绝这一配置。PID 数值应由本机底盘调试确定。

方向只换算一次：反馈端口保持电机原始角度符号，导航使用逻辑轮的 encoder_direction。必须先架空验证每个逻辑轮、ID 和正反方向，再低速落地。

CAN1 默认过滤器 bank 0；CAN2 默认 bank 14，分界为 14。如已有过滤器分配，须统一规划，避免两套驱动覆盖同一个 bank。

3. 打开编辑器并关联工程

运行本目录交付中的 foxmolika_MapEditor.exe，或安装独立编辑器安装包后点击“启动编辑器”。本地 beta 独立安装器只安装编辑器，不会向系统安装或替换 CubeMX .pack。

新电脑或尚未安装0.8.3底盘组件时，使用交付中的 CubeMX 一体安装器，它携带并自动导入底盘包。编辑器/助手标识为0.8.3.beta，底盘包保留CubeMX兼容的数字版本0.8.3。若已安装DeepSeek同号0.8.3底盘包，优先用独立编辑器；一体安装器遇到同号不同内容会拒绝覆盖，不要删除自己的包来绕过检查。

使用已经安装底盘组件的 CubeMX 工程：先 Generate Code，再在编辑器的工程关联入口选择该工程的 .ioc，导入该工程生成的 rcs_config.h，核对轮型、几何、电机 ID、方向和 CAN 总线。

第一次请使用复制的试验工程并另存地图。编辑器工具栏点击“应用与状态机…”打开新界面。

4. 配置“生成后上电执行”

在“应用与状态机…”中填写：启用应用及状态机、上电自动启动、CAN1/2、CAN 句柄、电机 ID、应用周期、反馈最大年龄和上电等待时间。句柄留空时按总线生成 hcan1 或 hcan2。

若每次上电前均已将实车放在 P0，且车头与 P0 朝向一致，勾选“确认每次实物位于P0”。这是一项摆放约定，不是传感器定位。没有这一约定时，关闭自动启动，启动前通过 App_task_SetStartPose 提供真实起点，再显式 App_Start。

默认状态表为“执行整条路线 → 完成”。完整配置后导出到关联工程，按下一节一次性加入 main 模板，即可在后续启动时按状态表执行，不需要再补一个 robot_route_task。

应用周期必须不小于速度环周期、不超过导航采样上限，并小于命令超时。示例常用速度环 5ms、应用 10ms；这不是硬件通用的调参结论。App_Init 还会复核地图与底盘配置是否一致，防止两边使用不同几何或 ID。

旧地图不会自动开启上电运动；打开后须明确完成上述配置。纯机构或等待状态机可以不含路线；没有 CAN 时仅支持这类不依赖底盘运动的状态，地图当前仍需至少两个合法航点。

5. main.c 固定模板：只接一次

在 CubeMX 的对应 USER CODE 区加入以下内容。保留 CubeMX 原有时钟、GPIO、CAN 初始化顺序。

/* USER CODE BEGIN Includes */
#include "app.h"
/* USER CODE END Includes */

/* GPIO/CAN等MX初始化全部完成后： */
/* USER CODE BEGIN 2 */
if (!App_Init())
{
    Error_Handler();
}
/* USER CODE END 2 */

while (1)
{
    /* USER CODE BEGIN 3 */
    App_Task();
    /* USER CODE END 3 */
}

自动启动在应用配置中开启；不要在 main 里再调用另一套导航调度器。App_Task 必须连续调用，不能在主循环中添加长时间 HAL_Delay 或等待动作完成的死循环。

本版没有自动修改 main.c。以上只需接入一次；之后修改状态机和航点，再保存地图、导出到关联工程即可。RTOS 项目可把同样入口放到持续运行的单个任务中；本版不自动生成 RTOS 线程和优先级配置。

6. 像航点动作一样编辑状态机

状态支持：自定义、运行整条路线、等待、完成。左侧管理状态和唯一初态；右侧填写状态属性与代码。转移列表管理目标和条件，顺序决定优先级：同一周期只有第一条为真的条件生效，目标状态到下一周期才进入。

  • 进入：进入该状态时执行一次，如下发夹爪目标。
  • 周期：每个应用周期执行，处理非阻塞机构任务。
  • 完成条件：C 表达式，用于自定义状态，如 gripper_is_ready()。
  • 离开：正常转移前执行一次。
  • 取消：活动状态被停止、超时或故障取消时执行一次。
  • 超时：超时触发故障；不是直接跳过该状态。

在转移条件中可用 context、elapsed_s 和 complete。例如 complete 表示本状态完成；elapsed_s > 2.0f 表示已运行超过两秒。运行路线状态的 complete 来自路线完成，等待状态来自设定时长，自定义状态来自完成条件。

示例：“夹爪准备 → 执行整条路线 → 等待1秒 → 完成”。夹爪准备的进入代码填你已有驱动的 gripper_open()；完成条件填 gripper_is_ready()；转移条件填 complete。需要的驱动头文件放在状态机公共头文件区。函数必须已在工程或编辑器公共代码中有定义；软件不会猜测任意夹爪、舵机或升降机构的通信协议。

所有代码以稳定 ID 生成 USER CODE 区。正常重新导出会保留用户区；生成区被手工修改、删除含自定义代码的状态或目标目录混入其他文件时，导出会拒绝覆盖。修改地图代码与生成后手工编辑同一用户区发生冲突时也会要求处理，不能靠强制覆盖丢代码。

旧0.8.3的安全钩子如果已经手工修改，而beta同时更换了该钩子的默认行为，升级会拒绝自动合并并保留原目录。请另存导出后人工核对，不能把旧的解锁/运行/故障处理不加检查地移进新状态机。

7. 航点动作与纠错的关系

航点仍分“到达后”和“离开前”两格。执行顺序为：行进到点、停稳、到达后动作、配置的独立观测纠错、离开前动作、前往下一点。

相对旋转、绝对旋转、等待和自定义机构动作仍在航点动作中配置。状态机中的整条路线状态负责调用它们，不会启动第二套路线引擎。内置旋转和等待无需非空机构上下文。

现有电机编码器会自动接入里程推算，不再要求手补反馈函数。没有 IMU、定位模块等独立观测设备时，纠错模板留空；编码器不能证明实车没有打滑，也不能凭里程计自证修正正确。引入独立硬件时仍需配置真实的读取适配函数。

旋转动作的车体中心来自轮型、安装角、半径、方向与速度闭环的一致配置。本版不会把“绕某轮旋转”的现象简单归结成航点写法，也不能用主机测试承诺消除了所有机械偏心。

8. 停止、故障与坡道

App_Stop 会取消当前状态和活动航点动作，停止路线，并禁止上电自动启动逻辑再次启动。故障也不会自恢复。重新确认车辆位置与故障原因后，显式 App_Init，再给位姿或按P0约定调用 App_Start；重复初始化不会重新触发自动启动。

健康底盘在已配置坡道上停车时，按坡道模块请求驻坡保持，并每个应用周期续期。底盘、接收或保持链路故障时会锁定零输出；电机电流保持不能替代失电机械制动。坡道参数、制动函数和真实机构应先完成验证。

下列接口供调试查看，首次故障在取消与锁定前保存：

App_task_State();          /* 应用：READY / RUNNING / FINISHED / FAULT / STOPPED */
App_task_Fault();          /* 配置、初始化、反馈、底盘、导航或状态机 */
App_task_FeedbackFault();  /* 角度非法、漏圈歧义、过期、FIFO溢出、总线关闭等 */
App_task_ChassisFault();
App_task_NavFault();
App_task_MachineFault();
App_task_FaultTick();
App_task_Holding();

原始角度跨越半圈且缺少足够采样时无法唯一还原圈数，所以接收间隔过大就报错，不按 RPM 猜位移。3000rpm 配置的默认最大帧间隔约5ms。调试暂停可能造成故障；不要在看门狗有效运行时靠修改 Watch 强制清错。

9. 已有 CAN 回调的工程

新工程默认生成一个强定义 HAL_CAN_RxFifo0MsgPendingCallback，自动处理本组件 CAN 的 FIFO0。其他 CAN 用户或已有同名回调不能由它静默接管。

已有分发器时，在编译宏中设置 RCS_CAN_PORT_DEFINE_HAL_CALLBACK=0，并在现有回调中调用 rcs_can_port_poll(hcan)；如果已有代码逐帧读取 FIFO，则每帧调用 rcs_can_port_on_rx。两种方式选一种，不要让两套代码读同一帧。

本版自动模式针对独占底盘反馈 FIFO 的工程；共享总线的其他业务帧、滤波器及回调需在已有分发器中统一处理。全新独占工程不需要手补上述回调。

10. 从旧地图与旧工程升级

先复制工程和地图。旧6/8文件、DeepSeek旧15/17文件的完整生成目录可升级到19/21；用户区保留。只有部分新版入口文件、无归属签名或在用户区外改过代码时会拒绝写入，并保留原目录。

已知官方旧生成后助手按文件摘要识别，升级使用独立 foxmolika_Tools_083_beta 目录，不覆盖旧助手。未知或自行修改的生成后命令会保留并阻止自动替换，需要先明确整合自己的分发脚本。

导出后在 Keil 重新加载工程。Application/foxmolikaRoute 分组应同时出现 app、machism、导航、反馈的 .c/.h；头文件是文件类型5，C源文件是文件类型1。不要再手动添加同名文件形成重复登记。

11. 验证边界与交付位置

本版验证报告以交付目录内的本轮报告为准；主机模拟、ARM编译、CubeMX生成与实车试验分别记录。没有连接电机和坡道进行实车验收，不能将“编译通过”称为“试车通过”。

完整源码在本文件上两级的独立 beta 工程目录。可运行编辑器、单文件独立编辑器安装器、示例地图、示例生成文件、教程和摘要集中在“交付”文件夹。编译中间件、私有日志和本轮测试现场留在 build，不混入用户示例。
