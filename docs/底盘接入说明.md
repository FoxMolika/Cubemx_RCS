# 独立 .c/.h 模块接入说明（0.5.0）

CubeMX 内直接生成的步骤见 [使用说明.html](使用说明.html)：安装套件 → Select Components 选择 RCS.foxmolika 0.5.0 → foxmolika 页面启用 Robotics foxmolika 模式 → 填写参数并保存关闭 .ioc → 安装器“关联工程…”主动关联该 .ioc → 重新打开 .ioc → Generate Code → Keil 重载。本文件侧重生成后的模块接口。

本包同时以 `dist/RCS.foxmolika.0.5.0.pack` 和合并安装器内嵌包两种形式发布，两处内容逐字节相同。

生成结果为 3 个 `.c` 和 4 个 `.h`。模块不定义 main，不创建任务，不定义全局 HAL_CAN 接收回调；配置器和样例导出脚本只向空目录写这些文件，不修改已有工程文件。

## 0.5.0：CAN依赖和自动头文件补全

修复用户tester123工程没有配置CAN时出现的CAN_HandleTypeDef等编译错误。安装后点“关联工程…”选择已保存的.ioc：工具合并.extSettings以启用CAN HAL驱动，并在CubeMX的生成后操作中登记工程内foxmolika_PostGenerate.exe。每个工程只关联一次，后续Generate Code自动登记4个头文件，不需要手动运行脚本。

关联工具支持F407 HAL + Keil MDK，能将已选用的foxmolika组件版本切换到0.5.0；旧RCS组件需先在CubeMX取消并更换；保留原.ioc和.extSettings备份，不覆盖已有的其他生成后操作。安装本身不会扫描或改写用户工程。实际硬件CAN1/CAN2引脚、波特率、滤波和中断仍需按接线配置；启用CAN HAL只保证驱动可编译，并不完成硬件初始化。

用户的0.3.3目录和test原工程保留。修复副本在源码目录的dist/tester123_fixed_0.5.0.zip；验证和版本比较见随源码的验证记录与“与DeepSeek版本对比”。

关联后自动补全rcs_chassis.h、rcs_control.h、rcs_hal.h和当前包含目录中的rcs_config.h，重复运行不会重复添加，首次修改保留.uvprojx.rcs-backup。不会向main.c插入底盘初始化、任务或回调。

## 文件依赖

`rcs_chassis` 为纯 C99 运动学；`rcs_control` 为纯 C99 闭环控制；`rcs_hal` 依赖 STM32F4 HAL、CMSIS 中断原语和 `rcs_config.h`。三个头文件都带 `extern "C"`，可直接被 C++ 文件包含。参数修改从生成器重新导出到新空目录，确认后自行替换模块。

目标是 STM32F407 HAL + M3508/C620。同一路 CAN、ID 1..4，可重排。当前不支持混合 CAN、2006/C610、VESC 或旧标准库。组件独占该 CAN 的发送邮箱和 0x200 的四个电流槽；三轮模式仍把未用槽清零。

## 编译期参数检查

CubeMX 界面只检查单项范围。`rcs_config.h` 在编译时额外检查组合约束，违反时编译直接报 `#error "RCS: ..."`，不会再出现"生成成功但 RCS_Init 返回 0、底盘不动"的情况：

- 在用轮子的电机 ID 两两不同（三全向轮忽略 W3）；
- 命令超时、反馈超时都大于控制周期；
- 方向只能为 ±1，电流上限 1..16384，布局 0..2，CAN 为 1 或 2。

## 对外接口

在你自己的 `chassis_task.c`、板级 `bsp_can.c` 或已有调度模块中调用：

| 接口 | 调用位置与条件 |
|---|---|
| `RCS_Init(CAN_HandleTypeDef *can)` | CAN 板级配置完成后，传入选定的句柄；检查返回值。只初始化底盘模块状态，不替代 HAL CAN 的引脚、时钟、过滤器、启动和通知设置。 |
| `RCS_OnCanRx(can, header, data)` | 已有 CAN 接收中断分发读出消息后传入。模块内部检查总线、帧类型、长度及 ID；不覆盖你现有的全局回调。 |
| `RCS_Process()` | 同一个底盘控制任务按配置的周期调用，默认 5 ms；锁定时也持续调用。 |
| `RCS_Arm()` | 显式解锁事件；只有所有在用电机反馈新鲜时成功。LOCKED 和 FAULT 状态都可调用，成功即清除故障；解锁后仍必须下达新命令才会动。 |
| `RCS_SetVelocity(vx, vy, wz)` | 解锁成功后下达新命令；按实际收到指令的节奏续期。命令超时进入故障状态并停止输出，需重新解锁。 |
| `RCS_Lock()` | 显式锁定，清除旧指令并尝试发送零电流。 |
| `RCS_State()` / `RCS_Fault()` | 查询状态和故障原因。 |

`RCS_Init / RCS_Arm / RCS_Lock / RCS_SetVelocity / RCS_Process` 由同一个任务串行调用；其他任务通过你自己的队列提交请求。ISR 只调用 `RCS_OnCanRx`，接收快照在短临界区内复制，PID 在任务侧运行。FreeRTOS 周期任务可使用 `vTaskDelayUntil`，确认毫秒到 tick 的转换不为零。

模块不会自动调用自身。你决定把接口接入现有任务或调度器；无需把底盘代码放进 main.c。

## 板级 CAN 的职责

在自己的板级 CAN 文件或 CubeMX 外设配置中完成以下工作：

- CAN1 或 CAN2 的 RX/TX 引脚、外设时钟和标称 1 Mbps 位时序。
- 可接收反馈 0x201..0x204 的过滤器，FIFO0 或你现有的消息接收路径。
- `HAL_CAN_Start`、接收通知、对应 NVIC 中断及 `HAL_CAN_IRQHandler` 分发。CAN2 还需要 CAN1 时钟及合理的过滤器组分配。
- 消息取出后把头和数据传给 `RCS_OnCanRx`；不要另定义第二个相同名字的 HAL 全局回调。
- **建议在 CubeMX 的 CAN 参数中开启 Automatic Bus-Off Management（AutoBusOff=ENABLE）**。模块直接读取 CAN_ESR 寄存器的 BOFF 位判断总线关闭，不依赖 HAL 错误中断；开启自动恢复后，总线修复即可恢复发送零帧，再显式解锁即可继续运行。未开启时外设会停在总线关闭状态，需要你自己重新初始化 CAN。

句柄通过 `RCS_Init` 参数传递，模块不要求外部必须声明名为 hcan1 的全局变量。生成的 CAN 选择用于验证句柄所属通道，不自动更改芯片配置。

## 发送邮箱

每帧发送前若邮箱未全空，模块先中止旧请求。已经在总线上发送的帧无法中止，模块最多等待 `RCS_TX_ABORT_WAIT_MS`（默认 2 ms，1 Mbps 下一帧约 0.13 ms）让它发完，仍未清空才报 `RCS_TX_FAILED`。需要更改时在编译选项中定义该宏。

## 几何、单位和轮序

界面填写轮径和完整轮中心距，单位 mm；内部使用 m、m/s、rad/s。坐标 x 向前、y 向左、逆时针角速度为正。

四麦轮为 X 型安装：W0 左前、W1 右前、W2 左后、W3 右后；逻辑正转朝向车头。三/四全向轮必须等半径、等角间隔、切向滚动；W0 位置角从 x 轴逆时针测量，后续轮依次增加 120°/90°。正转方向为该位置的逆时针切线 (-sinθ, cosθ)。三轮模式忽略 W3 参数，但保留其电流槽为零。

减速比为电机转子转速 / 轮子转速，包含全部传动。默认值 19.2032 对应 M3508 原装减速箱（3591/187）；加装外部传动时请乘上外部速比。方向同时作用于反馈和输出。C620 电流上限采用原始协议计数，不是 mA。

## 速度环

PID 的微分项作用在**测量值**上（−Kd·d(反馈)/dt），不作用在误差上：下达新速度、解锁瞬间都不会产生电流尖峰，Kd 只抑制实际转速变化。解锁和锁定时微分历史以当前反馈重新开始。默认 PID 全零，需要实车调参。发生超时后旧指令清除，反馈恢复不会自动重新运动；必须显式解锁并下达新命令。CAN 断线时无法保证零帧到达驱动器。
