# 门禁改进清单

0.8.8 发布中遇到的日志丢失、构建产物混用、旧验收报告和重复打包问题，现从同一套门禁入口处理。日常操作见 [版本与发布](版本与发布.md)。

| 问题 | 当前措施 | 验收方式 |
| --- | --- | --- |
| D1/D3、#6 日志与编码 | 原始 stdout/stderr 分文件，运行中查看，失败保留有界尾部。使用独立步骤目录 | 空格、中文、GBK、单行大输出、超时和重复步骤 |
| D2 重复执行 | 同工作区互斥，冻结目录按版本及提交区分 | 两进程竞争，完成后重新获取锁，已有候选拒绝覆盖 |
| #1 模板依赖 | 编辑器每次编译，记录真实输入并核对嵌入资源。生成后助手的缓存检查自身输入和输出摘要 | 真实 CSC 下修改模板内容观察运行输出。只改时间戳时输入摘要保持一致 |
| #2/#5/#17 历史与变更说明 | 正式发布预检检查快照和变更说明，历史原件逐项核对。历史路径可通过环境变量设置 | 隔离发布演练及历史摘要核对 |
| #3 判定 | 打包条件改为显式错误，保留检查阈值。门禁拒绝优化模式 | 离线发布预检与完整发布演练 |
| #4/#9/#10/#11 本轮证据 | 记录每轮和每步标识，前序证据封存。核对卸载前安装态与当前产物，打包前验证副本与原件 | 残留旧报告、安装路径消失、哈希变化及旧续跑记录 |
| #7/#8 保留策略 | 失败及发布轮保留。显式命令可清理较早的成功开发轮 | 按状态、层级和记录日期清理隔离夹具 |
| #14/#16/#18 测试与说明 | 门禁诊断测试纳入 host，发布文档覆盖候选、重试、归档和公开 | 离线诊断测试和发布预检 |

GitHub Actions 接入、各验收脚本工作目录的统一搬迁、跨全仓的 subprocess 调用审计可独立推进。现有 native 仍在具备 CubeMX/Keil 的 Windows 用户会话运行。
