# Claude 问题复核与本版动作入口

复核依据为本地源码、实际EXE测试和CubeMX原生生成结果，而非仅采纳审查文字。候选源目录保持不动，维护与发布在RCS_Chassis_CubeMX目录内。

| 提出的事项 | 判断与处理 |
|---|---|
| 设定速度变化导致微分冲击 | 原问题存在。沿用Claude/Fix的测量值微分实现，主机测试覆盖设定阶跃、测量变化、故障后恢复。 |
| HAL软件bus-off错误位会滞留/依赖IRQ | 原检测方式存在问题。使用CAN ESR.BOFF检测当前硬件状态；HAL桥接测试覆盖置位和恢复。 |
| 重复ID、超时与周期组合无检查 | 原问题存在。导出参数检查与生成配置头的#error约束已补齐；CubeMX界面没有新增跨字段实时红字提示，非法组合在编译时阻止。 |
| 中止发送后立即查邮箱误报 | 原问题存在。沿用有界等待实现，主机HAL桩测试覆盖正常清空及超时。 |
| Directory.Move跨卷失败 | 原实现风险存在。维护版本的安装事务优先在仓库同卷保留备份，并提供逐文件复制/校验的回退；本机没有两块实际卷的验收，不能把夹具测试等同跨盘实测。 |
| 旧版本并存 | 本身不是错误：旧工程可能仍引用旧版本。新版本保留旧包并明确提示。相同版本内容不同才是冲突，本版使用0.3.5独立目录并拒绝覆盖同版本不同内容。两个内容不同的0.3.1候选不能同时占用同一个仓库版本目录。 |
| 地图轮向遗漏、采样上限超过命令超时 | 原问题存在。导入轮向和命令超时，检查最大采样间隔严格小于命令超时；外接编码器仍需人工核对方向。 |
| Keil工程树不显示.h | 头文件在磁盘上并且包含路径已存在。实际CubeMX生成的MDK工程没有登记组件头文件；交付的KeilHeaders工具补4个头文件，重复运行幂等。重新Generate后需要再运行。不是“头文件没生成”，也不是补7个头文件。 |
| 日志含Keil许可信息 | 属于交付卫生问题，不能据此断言没有编译许可证。发布源码不含这些原始编译日志；本轮未做ARM完整链接，不把主机GCC测试当Keil目标链接。 |
| extern C、减速比19 | C++调用兼容性已补齐。默认值采用19.2032，但真实减速比应按所用电机/机构规格核实，不能认为任意底盘都固定这个值。 |
| README链接/版本、旧EXE与源码不一致 | 作为真实交付问题处理。新版本重新编译、测试同一安装EXE、核对内嵌PACK与dist字节一致，并提供当前说明和源码ZIP。 |
| .gitignore的build/未排除suite/build | 该断言不正确。未带根斜杠的目录模式build/也匹配嵌套build目录。本版源码ZIP还按允许目录打包，不带suite/build缓存。 |

本版预留夹爪、舵机和升降动作。选择航点→“航点动作…”；可在界面填写启动、完成条件、完成清理、取消清理，也可在独立rcs_actions.c的USER CODE区域手写。导出路径3C3H，不向main.c注入。重导出按稳定航点ID保留手写内容；冲突保留原文件并要求统一代码或另选输出目录。

完整使用说明见[航点动作说明](../map_editor/docs/航点动作说明.md)。夹爪/舵机/升降驱动需用户提供；本版验证为主机编译、仿真、动作生命周期与安装流程，未做真实机构验收。
